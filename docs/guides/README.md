# 使用者指南

面向从 PyPI 安装 `aeval-harbor` 后要**用起来**的人，不是面向项目内部开发者的
过程记录。三份指南彼此独立，按需要读：

| 指南 | 你会得到什么 | 读之前需要知道 |
| --- | --- | --- |
| [写一个评测套件](writing-a-suite.md) | 从零写出 `aeval` 能加载、校验、判分的套件；全字段参考；继承与合并语义；哪些事实不该写进套件；校验与运行的命令顺序；常见错误对照表 | 会 Python 和 YAML 即可；不需要先学 Harbor |
| [接入一个新的 agent](adding-an-agent.md) | 把自有 agent CLI 接进来评测：先选路径（零代码家族基座 / 写适配器类）、五步走、声明与实现一致性的硬规则、预算与模型协议的声明方式、运行时镜像映射、三条红线 | 读过[写套件](writing-a-suite.md)会更容易理解配对与能力门槛 |
| [指标语义与判分规则](metric-semantics.md) | 报告里每个状态词与数字的确切含义：两层判分、六项前置事实门（未成立即 `cannot_judge`，试次退出有效分母）、全部轨迹指标的公式/阈值/跳过条件、折叠顺序与 veto、`pass@k` 与 `pass^k`、怎么读一份报告、常见误读 | 已有一个套件或一份报告在手 |

## 这三份指南的边界

- 它们描述**当前代码的行为**。口径若有歧义，以代码为准。
- 它们不复述项目内部的开发过程记录。内部阶段记录、环境验证报告与设计规划稿既不随
  发行包分发，也不进这座公开仓库，因此不作为接口说明——对外表达一律以本目录的
  指南为准。
- 想看判分链路的可交互架构图，见 [`../diagrams/eval-chain.html`](../diagrams/eval-chain.html)；
  离线跑通整条判分链路见 [`../../examples/offline-chain/`](../../examples/offline-chain/)。
