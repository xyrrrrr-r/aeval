# 接入一个新的 agent

本指南面向已经从 PyPI 安装 `aeval-harbor`、想用自己的 agent CLI 跑评测的开发者。
读完你应该能：把 agent 变成能被 `aeval conformance` 验证、能被套件组合、能被证据链
记录的适配器。

结论先说：接入成本是**一个声明文件 +（多数情况下）一个适配器类**，不需要改框架核心。
仓库里已有三条真实路径可以对照：

| 文件 | 形态 |
| --- | --- |
| [`agents/dsh.yaml`](../../agents/dsh.yaml) + [`src/aeval/agents/dsh/agent.py`](../../src/aeval/agents/dsh/agent.py) | 自有控制栈、自有会话格式，pin 死在类里的适配器 |
| [`agents/deepagent.yaml`](../../agents/deepagent.yaml) + [`src/aeval/agents/deepagent/agent.py`](../../src/aeval/agents/deepagent/agent.py) | OpenAI 协议的 ACP CLI，pin 死在类里的适配器 |
| [`agents/fakeagent.yaml`](../../agents/fakeagent.yaml) + [`src/aeval/agents/testing/fake_agent.py`](../../src/aeval/agents/testing/fake_agent.py) | 非 Node、只产 ATIF 的最小参考适配器 |

契约代码在 [`src/aeval/agents/contract.py`](../../src/aeval/agents/contract.py)、
[`src/aeval/agents/declaration.py`](../../src/aeval/agents/declaration.py)、
[`src/aeval/agents/conformance.py`](../../src/aeval/agents/conformance.py)；
本指南里的每个类成员、每个允许值、每条报错都出自这些文件。

## 1. 先决定走哪条路

| | 零代码家族路径 | 写一个适配器类 |
| --- | --- | --- |
| 适用 | agent 是 **OpenAI 协议的 ACP CLI**：Harbor 的 ACP runner 能启动它，它的模型流量说 OpenAI 线（chat 或 responses） | 其它情况：自有 session 格式、非 ACP 启动方式、非 OpenAI 协议（例如直接讲 broker 线，或走 SDK JSON-RPC） |
| 要写什么 | 只写 `agents/<id>.yaml`；`import_path` 指向基座 `aeval.agents.openai_acp:OpenAiAcpAgent`，全部事实写在声明里 | 一个继承/结构性满足契约的类 + 一个声明，两侧逐字段一致 |
| 轨迹从哪来 | Harbor ACP runner 自己写的 `acp-summary.json` / `trajectory.json`，基座负责读回并映射 | 你自己把 agent 的 session 格式映射成 ATIF |
| 还要声明 | `launch.kwargs.registry_entry`（起哪个 CLI）、`model_routing`（协议与 env 拼写）、`control_stack` | `runtime`、`launch`、必要时 `control_stack` / `model_routing` |
| 参考 | 见第 6 节 | 第 3 节 |

判断口诀：**如果 Harbor 的 ACP runner 能替你把 CLI 起起来、并且 CLI 自己会说 OpenAI 协议，
就走零代码家族路径**；只要有一条不成立，就写类。

## 2. 三类事实归位

| 类别 | 例子 | 该放哪 |
| --- | --- | --- |
| agent 身份 / 能力 | `id`、`version`、`provides`、轨迹能力、是否需要控制栈、模型协议 | `agents/<id>.yaml` 声明 + 适配器类（运行期读取源） |
| 部署事实 | 安装前缀 `install_prefix`、npm 缓存 `npm_cache`、session reader 挂载点 `session_reader`、`override_setup_timeout_sec`、`run_timeout_sec` | 声明的 `launch:` 档案（**不是** job 文件） |
| 评测事实 | 任务集、判分器、上限、后端、尝试次数 | 套件（`suites/<id>/`）；job 文件只描述任务臂 |

为什么不能混：

- 把"这个 agent 的启动方式"抄进每个 job 文件，套件 × agent 就退化成文件的笛卡尔积；
  换成声明 + 组合器之后，一个配对只花一个声明（`aeval job` / `aeval run --agent`）。
- 把某个 agent 的 home 路径、某个控制栈的名字写死进核心，第二个 agent 就必须改核心。
  声明的存在就是为了让核心不认识任何 agent 名。
- 把评测上限写进 agent 声明同样错位：上限属于套件，agent 只能说"我能不能被计量"
  （见第 4 节）。

## 3. 五步走

### 3.1 用一条命令拿到骨架

```console
$ aeval new-agent --id myagent --provides acp_stdio,shell,file_tools \
      --mode acp_stdio --budget none --transcript-source native_session_via_bridge
scaffolded agent myagent:
  wrote src/aeval/agents/myagent/agent.py
  wrote agents/myagent.yaml
next: implement read_trial_session(), then run `aeval agents` and `aeval conformance --agent agents/myagent.yaml`
```

`aeval new-agent` 的真实开关（来自 [`src/aeval/agents/scaffold.py`](../../src/aeval/agents/scaffold.py)
与 [`src/aeval/cli.py`](../../src/aeval/cli.py)）：

| 开关 | 默认 | 允许值 / 说明 |
| --- | --- | --- |
| `--id` | 必填 | agent id；只允许字母数字和 `-` `_` |
| `--mode` | `installed_cli` | `installed_cli` \| `acp_stdio` \| `sdk_jsonrpc` |
| `--provides` | `shell` | 逗号分隔的能力名 |
| `--budget` | `none` | `none` \| `wallclock_kill`；`gateway_lease` 会被生成器拒绝（它要求沙箱内控制栈，生成器不替你写），先声明 `none`，控制栈就绪后在类和声明里同时改成 `gateway_lease` |
| `--transcript-source` | `atif_native` | `atif_native` \| `native_session_via_bridge` |
| `--agents-dir` | `agents` | 声明目录 |
| `--package-dir` | `src/aeval/agents` | 适配器模块写到哪（PyPI 安装场景应指向你自己的包） |
| `--import-path` | 自动 | 覆盖生成的 import path |
| `--force` | 关 | 覆盖已存在的声明 |

生成器还要求 `agents/_base/agent.base.yaml` 存在，否则直接拒绝。如果你不在仓库布局里，
先在该路径放置基座（内容就是下面这些键）：

```yaml
schema_version: 1
budget_enforcement: none
write_surface: ephemeral_overlay
server_side_session: forbidden
observations: []
provides: []
```

生成的声明长这样（真实内容，注释为生成器自带）：

```yaml
# Generated by `aeval new-agent`. Values must agree with the adapter class:
# a declaration that drifts from its class is an error, not a silent winner.
extends: _base/agent.base.yaml

id: myagent
version: "1"
import_path: "aeval.agents.myagent.agent:MyagentAgent"

mode: acp_stdio
budget_enforcement: none
write_surface: ephemeral_overlay
provides:
  - acp_stdio
  - file_tools
  - shell

transcript:
  source: native_session_via_bridge
  reader: myagent-reader
  capabilities:
    - native_session_via_bridge
  # 注释从略。`unavailable` 是诚实的起点：还没观测过的字段不能被声称可用。
  fields_available:
    events: unavailable
    token_usage: unavailable
```

生成的 `agent.py` 关键部分（节选）：

```python
class MyagentAgent:
    ADAPTER_ID = "myagent"
    ADAPTER_VERSION = "1"
    ADAPTER_MODE = "acp_stdio"
    PROVIDES = frozenset({"acp_stdio", "file_tools", "shell"})
    BUDGET_ENFORCEMENT = "none"
    WRITE_SURFACE = "ephemeral_overlay"
    SESSION_RECORD_OUTPUT = "agent_session_record"
    REQUIRED_OBSERVATIONS = ()

    name = "myagent"
    version = "1"
    # 骨架的 __init__ 里设置 self.agent_session_id = None

    def read_session_record(self) -> bytes:
        raise NotImplementedError("read the myagent official session record and return its bytes")

    def read_trial_session(self) -> CanonicalTranscript:
        raise NotImplementedError(
            "read the myagent session format and map it to ATIF "
            "(events, token usage, stop reason)"
        )
```

骨架**已经满足契约**：成员齐、声明可解析、词表合法。`read_trial_session()` 故意抛
`NotImplementedError`，于是 conformance 会把轨迹检查记成 **skipped 并带上这句话**，
而不是假装它可用。`read_session_record()` 同样故意抛错：收集阶段会 fail closed，
不会写一份伪造的会话记录。

### 3.2 实现适配器类

放在 `src/aeval/agents/<id>/agent.py`（`--package-dir` 可改）。契约是**结构性**的：
不要求继承某个基类，只要求成员存在——框架在试次开始前逐个检查。

证据链会读的成员（缺一个就在起跑前被拒，而不是在收集途中抛 `AttributeError`）：

| 成员 | 必需 | 说明 |
| --- | --- | --- |
| `name` | 是 | agent 名 |
| `version` | 是 | agent 版本 |
| `paths()` | 是 | 产物位置对象（基座用它能找到日志目录） |
| `read_trial_session()` | 是 | 返回 `CanonicalTranscript`（ATIF + 元数据信封） |
| `read_session_record()` | 是 | 返回官方会话记录的字节；读不到就抛错 |
| `SESSION_RECORD_OUTPUT` | 是 | 这份记录属于哪个 collect 槽位 |
| `agent_session_id` | 是（或有旧别名 `dsh_session_id`） | agent 自己的会话 id；**不要**命名为 `session_id`，那个名字属于 Harbor 的沙箱会话 |

运行期读取的类属性（声明会与它们逐字段对账，见 3.3）：

| 属性 | 必需 | 允许值 / 说明 |
| --- | --- | --- |
| `ADAPTER_ID` | 是 | 与声明的 `id` 相同 |
| `ADAPTER_VERSION` | 是 | 适配器自身版本（观测到的 agent 版本另行记录） |
| `ADAPTER_MODE` | 是 | `installed_cli` \| `acp_stdio` \| `sdk_jsonrpc` |
| `TRANSCRIPT_CAPABILITY` | 是 | `TranscriptCapability(source=..., reader=..., capabilities=[...], fields_available={...})`；`source` ∈ `native_session_via_bridge` \| `atif_native`；`fields_available` 的每个状态 ∈ `ok` \| `partial` \| `unavailable` |
| `BUDGET_ENFORCEMENT` | 是 | `gateway_lease` \| `wallclock_kill` \| `none`（见第 4 节） |
| `PROVIDES` | 是 | 能力名集合；推荐词表 `acp_stdio` / `sdk_jsonrpc` / `shell` / `file_tools` / `resume` / `atif_native`，也允许自造名字（套件的 `driver.require` 必须能对上） |
| `WRITE_SURFACE` | 否 | `ephemeral_overlay`（默认） \| `persistent` |
| `SERVER_SIDE_SESSION` | 否 | `forbidden`（默认） \| `allowed_declared` |
| `REQUIRED_OBSERVATIONS` | 否 | 需要在沙箱里实测并回绑的运行时事实，如 `("node",)` |
| `SANDBOX_HOME` | 否 | agent 自己的 state 放在沙箱哪里 |
| `SESSION_ARTIFACT_DIR` | 否 | 会话产物落在 bundle 的哪个位置 |
| `SESSION_RECORD_OUTPUT_PATH` | 视情况 | **非内置槽位必需**：记录在 trial 目录内的固定相对路径 |
| `CONTROL_STACK` | 否 | 沙箱内控制栈名（见第 4、5 节） |
| `MODEL_ROUTING` | 否 | 模型路由（见第 5 节） |
| `TERMINAL_DESCRIPTOR_OWNER` | 否 | `sandbox`（默认） \| `host`：谁能对试次终止状态发言 |
| `SANDBOX_SESSION_RECORD` | 否 | 官方记录是沙箱内单个已知文件时，给出它的绝对路径 |
| `locate_session_record()` | 否 | 记录形状特殊时，由适配器提供这个方法自己定位；框架通过模块级常量 `SESSION_RECORD_LOCATOR_ATTR`（它的值就是这个方法名）找到它 |
| `session_id_from_record()` | 否 | 记录里自带会话 id 时，由适配器解析 |
| `official_release_lock` | 否 | 固定发布锁，值必须是 `AgentReleaseLock` 或 `DshReleaseLock` 实例 |

`SESSION_RECORD_OUTPUT` 的规则：内置槽位是 `dsh_session` 和 `agent_session_record`，
它们有框架已知的固定路径；任何其它名字都算"自定义槽位"，必须是小写 slug，并且必须
同时声明 `SESSION_RECORD_OUTPUT_PATH`（trial 目录内的相对路径，不能绝对、不能含 `..`）。

`read_trial_session()` 的三个要点：事件、token usage、stop reason。
`stop_reason` 只能是 `agent_exit_0` / `agent_exit_nonzero` / `agent_claimed_done` /
`budget_exhausted` / `timeout_killed` / `crashed` / `infra_error`。
读取器要 fail closed——缺文件、解析失败都抛错，绝不返回一份"看起来完整"的轨迹。
两个真实实现可以抄：[`src/aeval/agents/openai_acp.py`](../../src/aeval/agents/openai_acp.py)
（读 Harbor 的 ATIF 转换）、[`src/aeval/agents/dsh/atif_mapper.py`](../../src/aeval/agents/dsh/atif_mapper.py)。

### 3.3 写声明 `agents/<id>.yaml`

```yaml
extends: _base/agent.base.yaml      # 只能继承 _ 前缀下的基座，不能继承别的 agent 的声明

id: myagent
version: "1"
import_path: "aeval.agents.myagent.agent:MyagentAgent"

mode: acp_stdio
budget_enforcement: none
write_surface: ephemeral_overlay
server_side_session: forbidden

provides: [acp_stdio, shell, file_tools]
observations: []
transcript:
  source: native_session_via_bridge
  reader: myagent-reader
  capabilities: [native_session_via_bridge]
  fields_available: {events: ok, token_usage: partial}

sandbox_home: /logs/agent/my-home
session_artifact_dir: .

# 会话记录槽位不是内置两个之一时，用 artifacts 条目镜像固定路径
# artifacts:
#   - {name: my-session-record, slot: my_session, path: sessions/session.jsonl}

# 运行时需求：沙箱里必须存在这个 CLI（key 与 agents/_runtime/images.yaml 对账）
runtime:
  key: myagent
  needs:
    - myagent CLI 已烘焙进镜像

# 部署事实：按环境给档案，job 文件因此不必再抄一份
launch:
  default:
    override_setup_timeout_sec: 900
    kwargs: {install_prefix: "/dev/shm/mypkg"}
```

声明与类**必须逐字段一致**，不一致是**硬错误，不是优先级规则**。被比对的字段：
`id` / `mode` / `budget_enforcement` / `write_surface` / `server_side_session` /
`transcript`（整体）/ `provides` / `observations` / `control_stack` /
`model_routing`（协议 + env）/ `terminal_descriptor_owner` / `sandbox_session_record` /
`artifacts` 的槽位名与固定路径 / `sandbox_home` / `session_artifact_dir`。
`version` 不参与比对：声明说的是适配器版本，运行期记录携带的是观测到的版本。
类始终是运行期读取源，这只有在"声明被证明一致"的前提下才安全——所以两者不一致时
`aeval agents` 与组合期直接失败。

声明是 `extra="forbid"`：写错的键会直接报错，不会被忽略。`schema_version` 只接受 `1`。

### 3.4 验证：`aeval agents` 与 `aeval conformance`

```console
$ aeval agents --agents-dir agents
agent deepagent v1 mode=acp_stdio budget=gateway_lease provides=['acp_stdio', 'file_tools', 'shell'] observations=[] extends=['_base/agent.base.yaml']
agent dsh v1 mode=acp_stdio budget=gateway_lease provides=['acp_stdio', 'file_tools', 'resume', 'sdk_jsonrpc', 'shell'] observations=['node'] extends=['_base/agent.base.yaml']
agent myagent v1 mode=acp_stdio budget=none provides=['acp_stdio', 'file_tools', 'shell'] observations=[] extends=['_base/agent.base.yaml']
3 agent declaration(s) agree with their adapter classes.
```

`aeval agents` 会逐条打印解析后的声明字段（id / version / mode / 记账能力 / 能力集合 /
观测 / 继承来源），并把它与解析出的适配器类逐字段对账，任何一处不一致都会让整条命令失败——
这就是"声明与实现不会悄悄漂移"的执行方式。它打印的是声明字段，不打印解析出的类或
`import_path`。

```console
$ aeval conformance --agent agents/myagent.yaml --suite suites/deepagent-hello
conformance: aeval.agents.myagent.agent:MyagentAgent
  [pass] declaration: myagent: _base/agent.base.yaml -> myagent.yaml
  [pass] contract: members present; id=myagent mode=acp_stdio observations=[]
  [skipped] model_routing: adapter declares no MODEL_ROUTING; control_stack=None
  [pass] capabilities: provides ['acp_stdio', 'file_tools', 'shell'] required by the suite; session record 'agent_session_record'
  [skipped] accounting: no suite budget given; enforcement='none'
  [skipped] transcript: read_trial_session() raised NotImplementedError: read the myagent session format and map it to ATIF (events, token usage, stop reason) — exercised but nothing was recorded to read
  -> OK (0 failed, 3 skipped)
```

六组检查，各对应一种"第二个 agent 会**静默**搞坏评测"的方式：

| 检查组 | 它守的是什么 |
| --- | --- |
| `declaration` | 声明能解析，且与适配器类一致 |
| `contract` | 证据链要读的成员与声明都在，不会在收集途中抛 `AttributeError` |
| `model_routing` | agent 说哪种线，部署能不能服务它（见第 5 节） |
| `capabilities` | 套件的 `driver.require` 在**建沙箱之前**被满足；会话记录槽位也对得上 |
| `accounting` | 套件有上限时，agent 的记账能力能不能真的让上限生效（见第 4 节） |
| `transcript` | `read_trial_session()` 真返回 ATIF，或者抛错；绝不能返回"像完整其实不完整"的东西 |

**跑不了的检查记 `skipped`，绝不算通过**。"没验到"和"验过了"是两个不同的事实。
`--suite` 可以重复给多个套件；不传 `--suite` 时能力与记账检查会记 skipped。
需要构造参数的适配器无法被实例化，轨迹检查同样如实记 skipped。

### 3.5 组合并跑一轮

下面用一个仓库里已经接好的适配器（`deepagent`）走一遍这条链，命令与你的 `myagent` 完全一致。
你的 `myagent` 还要先在 `agents/_runtime/images.yaml` 里给这个配对补一行，否则 `aeval check`
会像第 7 节那样拒绝（镜像表只对已登记的 pairing 放行）。

```console
$ aeval check --suite suites/deepagent-hello --agent deepagent
pairing deepagent × deepagent-hello: composed (impl=aeval.agents.deepagent.agent:DcodeAgent, attempts=5)
runtime deepagents-code for deepagent: (rides the task image)
runtime image check: OK

$ aeval job --suite suites/deepagent-hello --agent deepagent --profile default
job deepagent-hello: suite=deepagent-hello agent=deepagent profile=default attempts=5 impl=aeval.agents.deepagent.agent:DcodeAgent
Composed for a pairing: the job file's task arm is unchanged and the agent entry comes from the declaration. Nothing was executed.

$ aeval run --suite suites/deepagent-hello --agent deepagent \
      --run-dir runs/deepagent-1 --store runs/aeval.sqlite
composed for agent deepagent (profile default): aeval.agents.deepagent.agent:DcodeAgent
...
run run-deepagent-1 sealed: ... trial(s) recorded, ... file(s) attested, recompute passed
```

`aeval check` 只读，什么都不建，并会核对运行时镜像表是否覆盖这个配对（见第 7 节）；
`aeval job` 只打印组合结果；`aeval run` 才真正委托 Harbor 执行，并在 Harbor 退出码为 0
之后独立核对整条链路是否完整——Harbor 退出 0 不等于评测完成。
`--run-dir` 不能是已存在的目录，也不能落在套件目录里；`--store` 是 SQLite 库路径。
另有 `aeval probe --suite <套件目录>`：只校验套件的原生声明，不起 agent、不拉数据集。

跑完要核对三件事——这才是"接入成功"的定义：

1. **运行锁里有它**：`<run-dir>/runtime_lock.json` 的 `agents` 段应出现该 agent 的发布锁
   （读取接口是 `RuntimeLock.agent_locks()`）。锁由适配器的 `official_release_lock` 类属性
   贡献；没有固定发布的适配器不贡献条目，这不是失败。
2. **记录里是它**：`TrialRecord.adapter` 的 `id` 必须等于声明的 `id`，`version` 是运行期
   观测到的版本（拿不到实例时退回声明的 `ADAPTER_VERSION`）。
3. **封存证据能复算**：`aeval recompute <bundle_dir>` 独立复算通过，`runtime_lock_digest`
   与原值一致。

## 4. 预算声明要诚实

`BUDGET_ENFORCEMENT` 是一个**事实声明**，不是配置开关。

| 值 | 含义 |
| --- | --- |
| `gateway_lease` | 模型流量走网关，沙箱内的控制栈在执行记账；上限能在沙箱里真的触发 |
| `wallclock_kill` | 未走网关租约：模型流量不经网关，花费无法计量（带上限的套件同样拒绝） |
| `none` | 模型流量不经网关，花费无法计量 |

`gateway_lease` 的成立条件是**两件事同时为真**：模型流量确实走我们的网关，并且有一个
沙箱内控制栈在执行记账。如果新 agent 用它自己的 API key 直连模型，只能声明 `none`——
这不是"降级"，而是**诚实**。带上限的套件会因此拒绝它，而不是跑完之后给一个不能说明
花了多少的判定：

```text
suite caps spend ({'max_tokens': ...}) but myagent declares budget_enforcement='none' — its model
traffic is not metered by the gateway lease, so the cap cannot fire and the run would overspend
silently. Run with --accept-unmetered-budget to record the gap explicitly instead.
```

`--accept-unmetered-budget` 不是绕过检查，而是把"我知道这笔账记不了"写进运行清单
（`RunManifest.accepted_unmetered_budget`）。声称 `gateway_lease` 却**没有**声明
`CONTROL_STACK` 会被直接拒跑——否则会变成"记录里记了账、现实里没记账"：

```text
CONTROL_STACK (BUDGET_ENFORCEMENT='gateway_lease' is enforced by the in-sandbox control stack;
without it the spend would never be measured)
```

一次运行选了多个记账能力不同的适配器时，运行级记账点记为 `mixed`，不会声称一个它并不
拥有的单一记账点。

## 5. 模型的两种协议

模型流量有两条线，接哪个 agent 就按需注入哪条。`model_routing` 是声明里的一个事实，
不是部署脚本的口头约定。

| agent 说的协议 | `agent_protocol` | 需要服务哪些端点 | 例子 |
| --- | --- | --- | --- |
| 控制栈的传输本身就说 broker 线 | `gateway_native` | 不需要 façade，不注入任何 env | DSH（沙箱内插件即控制栈） |
| OpenAI chat（`POST /v1/chat/completions`） | `openai_chat` | `chat_completions` | 多数 OpenAI 兼容 CLI |
| OpenAI responses（`POST /v1/responses`） | `openai_responses` | `responses` | dcode |

声明写法（env 拼写是"这个 CLI 读哪个环境变量"，不是框架的选择）：

```yaml
model_routing:
  agent_protocol: openai_responses        # gateway_native | openai_chat | openai_responses
  env:
    base_url: OPENAI_BASE_URL             # 必需（非 gateway_native 时）
    alt_base_url: OPENAI_API_BASE         # 可选：同一 CLI 的第二种基础 URL 拼写
    api_key: OPENAI_API_KEY               # 必需（非 gateway_native 时）
control_stack: deepagent-facade           # openai_* 协议必需：能翻译该协议的控制栈
```

规则：

- `env` 的槽位只有 `base_url` / `alt_base_url` / `api_key`；值必须是合法的环境变量名。
  缺 `base_url` 或缺 `api_key` 会被拒——那是 CLI 找不到 façade 的典型形态。
- **双向对账，不一致直接拒跑**：
  - `openai_*` 协议必须有一个会翻译它的控制栈。判定依据是控制栈注册的能力
    （`serves_protocols`），不是栈的名字；仓库里当前注册的翻译栈是 `deepagent-facade`，
    它声明服务 `openai_chat` 与 `openai_responses`。缺了就是 agent 直连厂商：账面记了账、
    现实没记账。真实报错：
    `MODEL_ROUTING.agent_protocol='openai_chat' speaks an OpenAI wire; no CONTROL_STACK is declared to translate it — the agent would run unmetered`
  - 反向，声明了翻译栈却没有 `openai_*` 协议也会被拒（栈会服务一个没人调的端点）：
    `MODEL_ROUTING (the declared control stack translates an openai_* protocol; without that declaration the stack would serve nothing the agent speaks)`
- 两条规则同时由声明缺口检查与 `aeval conformance` 的 `model_routing` 检查项执行。
- **缺省不猜**：没有 `model_routing` 的适配器在 conformance 里记 `skipped`，不是 pass。
- 协议通过时的 conformance 输出会把推导出的端点与注入的 env 一起打出来，例如：
  `openai_responses via 'deepagent-facade'; the stack serves ['responses']; agent env alt_base_url=OPENAI_API_BASE, api_key=OPENAI_API_KEY, base_url=OPENAI_BASE_URL`

## 6. 零代码路径详解

如果新 CLI 属于"OpenAI 协议的 ACP CLI"这一族，把 `import_path` 指向基座，事实全部写在声明里：

```yaml
extends: _base/agent.base.yaml

id: myagent
version: "1"
import_path: "aeval.agents.openai_acp:OpenAiAcpAgent"   # 基座，不是某个具体 agent

provides: [acp_stdio, shell, file_tools]
mode: acp_stdio
budget_enforcement: gateway_lease
control_stack: deepagent-facade
terminal_descriptor_owner: host

model_routing:
  agent_protocol: openai_chat
  env: {base_url: MY_BASE_URL, api_key: MY_API_KEY}

transcript:
  source: native_session_via_bridge
  reader: harbor-acp-runner
  capabilities: [atif_via_bridge, token_usage]
  fields_available: {events: ok, token_usage: partial}

launch:
  default:
    kwargs:
      registry_entry:                    # "起哪个 CLI" 是声明事实
        id: my-cli
        name: My CLI
        version: "0.1.0"
        description: mycli exposed as an ACP server
        distribution:
          local: {cmd: mycli, args: ["--acp"], env: {}}
```

物化怎么发生：`adapter_class()` 把声明的字段变成**完整的适配器类**——`build_adapter_spec`、
证据门禁、conformance 读的都是这个物化类；Harbor 的 `import_path` 以
`aeval.agents.openai_acp:agent_<id>` 惰性物化同一个类（id 转小写、非 `[a-z0-9_]` 换成 `_`），
所以组合与运行即使跨进程也一致。基座提供行为：ACP runner 的 summary/trajectory 读回、
façade env 注入、registry entry 合并；声明提供事实：身份、能力、协议与 env 拼写、沙箱布局。
基座还固定声明了 `SESSION_RECORD_OUTPUT = "agent_session_record"`，所以套件的
`driver.session_record` 要写成同一个槽位。

`launch.kwargs.registry_entry` 里的 `distribution` 必须**恰好有一种**启动方式
（`local` / `binary` / `uvx` / `npx`），否则报
`the ACP registry entry must declare exactly one ACP distribution kind`。

两条硬边界：

1. **裸的 `OpenAiAcpAgent` 基座不是 agent**。它没有模型路由声明，也没有默认的 registry entry；
   `aeval agents` / conformance 会拒收它——"哪个 CLI"只有声明或 pin 能说。直接用基座构造会报
   `launches no CLI: no registry_entry kwarg (declare it in the agent's launch profile) and no
   default_registry_entry() pin — the declaration must say which ACP server to run`。
2. **会话记录必须是 Harbor ACP runner 自己写的那两个文件**：agent 日志目录下的
   `acp-summary.json` 与 `trajectory.json`。如果你的 agent 会话格式是自有的，就走写类路径，
   覆盖 `read_session_record()` / `read_trial_session()`，不要试图让基座去理解新格式。

## 7. 这个 agent 在沙箱里跑得起来吗

agent 的 CLI 必须**存在于沙箱里**，这不是声明能凭空变出来的：沙箱由任务自己的 Dockerfile
（或运营者指定的、钉了摘要的镜像）构建。配错的表现是"跑到一半 command not found"，
那时沙箱已经建好、预算已经开始烧。所以这个事实拆成两半：

- **声明说需要什么**：`runtime: {key: <slug>, needs: [...]}`。`key` 必须是小写 slug
  （形如 `^[a-z][a-z0-9-]*$`），`needs` 是非空字符串列表，人类可读、用于报错与审计。
- **映射表说在哪里满足**：[`agents/_runtime/images.yaml`](../../agents/_runtime/images.yaml)，
  每行是 `{suite, runtime, image, platform, note}`。`_` 前缀让声明发现不会把它当 agent；
  可用环境变量 `AEVAL_RUNTIME_IMAGES` 指向别处。

```yaml
schema_version: 1
images:
  - suite: tbench-pilot
    runtime: dsh
    image: null            # 刻意写下来：这个配对就走任务镜像
  - suite: my-suite
    runtime: myagent
    image: "registry.internal/myagent@sha256:..."   # 钉了摘要
    platform: arm64                                  # 钉了镜像就必须给 platform
    note: myagent 已烘焙进该镜像变体
```

三种结果，全部显式：

| 表里怎么写的 | 行为 |
| --- | --- |
| 钉了镜像 | 运行必须用**同一个**摘要与 platform（不一致即拒） |
| `image: null` | 这个配对刻意走任务镜像，对运营者没有额外要求 |
| 没有这一行 | **拒绝**并给出修法：往表里加一行，或显式 `--sandbox-image ref@sha256:... --sandbox-platform <arch>` |

组合之前先问一遍（只读，什么都不建）：

```console
$ aeval check --suite suites/tbench-pilot --agent dsh
pairing dsh × tbench-pilot: composed (impl=aeval.agents.dsh.agent:DshAgent, attempts=3)
runtime dsh for dsh: (rides the task image)
runtime image check: OK

$ aeval check --suite suites/deepagent-hello --agent myagent     # 未映射
pairing myagent × deepagent-hello: composed (impl=aeval.agents.myagent.agent:MyagentAgent, attempts=5)
runtime myagent for myagent: (no row)
runtime image check: FAILED
  no sandbox image is mapped for suite 'deepagent-hello' × runtime 'myagent' (needs: myagent CLI 已烘焙进镜像); add a row to <...>/agents/_runtime/images.yaml or pass --sandbox-image ref@sha256:... --sandbox-platform <arch>
```

几点补充：

- 声明里没有 `runtime` 时，检查会打印 `runtime: none declared — nothing to host, nothing to check`
  并以 0 退出——没有东西要托管，就没有东西要检查，这不是隐式通过。
- 组合后的 import path 无法回指到某个声明时，会打印
  `runtime: no declaration found for <import_path> — not checked`，而不是假装检查过。
- 表里钉了镜像的行在解析期就要求 `platform`，并且 `image` 必须含 `@sha256:`；
  `--sandbox-image` 也只接受钉了摘要的引用，且必须同时给 `--sandbox-platform`。

## 8. 临时换 agent

套件声明它期望的证据形态（`driver.session_record`，版本化、可审计的默认）；临时配对用
命令行，且**被记录**。套件说 `dsh_session`、适配器产出 `agent_session_record` 时，
不带覆盖就是直接拒绝：

```console
$ aeval check --suite suites/tbench-pilot --agent deepagent
pairing deepagent × suites/tbench-pilot: REFUSED
  <job 文件路径>: session-record flavor mismatch — the suite's collect plan uses 'dsh_session' but aeval.agents.deepagent.agent:DcodeAgent produces 'agent_session_record'; align the suite's driver.session_record with the adapter's SESSION_RECORD_OUTPUT
```

```console
$ aeval run --suite suites/deepagent-hello --agent deepagent \
      --run-dir runs/dcode-1 --store runs/aeval.sqlite \
      --session-record agent_session_record
composed for agent deepagent (profile default): aeval.agents.deepagent.agent:DcodeAgent
session-record override: 'agent_session_record' (suite declares 'agent_session_record') — recorded in the run manifest
...
```

规则：

- 覆盖值必须**等于所选适配器实际产出的 `SESSION_RECORD_OUTPUT`**（它是"用这个 agent 的形态"，
  不是绕过配对门）；否则上面那条 flavor mismatch 就是结果。
- 覆盖值必须是小写 slug。
- 它写进 `run_manifest.json` 的 `session_record_override`，所以这次运行记得自己用了哪种
  证据形态；即使覆盖值恰好等于套件声明的值，也会被记录。
- `--session-record` 只存在于 `aeval run`；`aeval check` 没有这个开关，只读检查仍按套件
  声明的槽位判定。运行时先跑能力、会话槽位、运行镜像、预算门，任何一道拒绝都会先发生，
  覆盖不改变这些门的结论。
- 跑出价值的配对，应该**固化成套件变体**（新文件，不动已封存的字节）。

## 9. 三条红线

1. **不要改已封存套件 / job 文件的字节**：摘要变了，旧证据就无法原值重算。新配对一律用
   声明与生成器，必要时新增套件变体，不修改既有文件。
2. **不要在核心代码里写 `if agent == "..."`**：需要按 agent 区分的行为应当是**声明**，
   由适配器给出。核心只保留与 agent 无关的序列。
3. **不要为了"跑通"而把 `BUDGET_ENFORCEMENT` 从 `none` 改成 `gateway_lease`**：记账能力
   决定套件能不能带上限跑，改它是把一个财务事实变成一句谎。

## 10. 排错表

| 症状 | 可能原因 | 修法 |
| --- | --- | --- |
| `agent <id>: declaration disagrees with <import_path>: mode: declaration=... adapter=...` | 声明与类漂移 | 让两侧逐字段一致；用 `aeval agents` 定位 |
| `contract: missing members [...] — the evidence chain reads them at trial end` | 缺 `name`/`version`/`paths`/`read_trial_session`/`read_session_record`/`SESSION_RECORD_OUTPUT`，或缺 `agent_session_id` | 补齐成员；会话 id 不要命名为 `session_id` |
| `declares no ['ADAPTER_ID', ...]` | 类缺声明属性 | 补 `ADAPTER_ID` / `ADAPTER_VERSION` / `ADAPTER_MODE` / `TRANSCRIPT_CAPABILITY` / `BUDGET_ENFORCEMENT` |
| `declares a value outside the contract's vocabulary` | `mode` / `budget_enforcement` / `write_surface` / `server_side_session` / `transcript.source` 不在词表 | 按报错里列出的允许值改 |
| `which is a pinned adapter class, not a declaration-driven base` | 声明指向了一个 pin 死的类，却按家族基座使用 | 要么把 `import_path` 指向真正的行为基座，要么去掉声明驱动的假设 |
| `launches no CLI: no registry_entry kwarg ... and no default_registry_entry() pin` | 零代码路径的声明缺 `launch.kwargs.registry_entry` | 在 launch 档案里写 registry entry（含 id/version/distribution） |
| `the ACP registry entry must declare exactly one ACP distribution kind, found [...]` | registry entry 里 0 个或多个启动方式 | 只保留一种（`local` / `binary` / `uvx` / `npx`） |
| `the selected agent cannot serve this suite — driver.require=[...], ..., missing [...]` | 能力名不匹配（打错字也会这样） | 改声明的 `provides` 或套件的 `driver.require`，让词表对上 |
| `session-record flavor mismatch — the suite's collect plan uses 'x' but ... produces 'y'` | 套件槽位与适配器 `SESSION_RECORD_OUTPUT` 不一致 | 对齐 `driver.session_record`，或临时用 `aeval run --session-record <适配器槽位>` |
| `declares session-record slot 'x', which the framework has no built-in path for — declare SESSION_RECORD_OUTPUT_PATH` | 自定义槽位缺固定路径 | 声明 `SESSION_RECORD_OUTPUT_PATH`（相对、不可逃逸），并在声明的 `artifacts` 里镜像同一路径 |
| `MODEL_ROUTING.agent_protocol='openai_chat' speaks an OpenAI wire; ... translate it — the agent would run unmetered` | 说了 OpenAI 线，但没有能翻译它的控制栈 | 声明 `control_stack` 为注册了该协议能力的栈，或改协议 |
| `MODEL_ROUTING (the declared control stack translates an openai_* protocol; ...)` | 声明了翻译栈，却没有 `openai_*` 协议 | 补 `model_routing.agent_protocol` 与 env 拼写，或去掉该控制栈 |
| `CONTROL_STACK (BUDGET_ENFORCEMENT='gateway_lease' is enforced by the in-sandbox control stack; ...)` | 声称网关租约却没有控制栈 | 声明 `CONTROL_STACK`；确认不了就诚实地改回 `none` |
| `suite caps spend (...) but <id> declares budget_enforcement='none' ...` | 带了上限的套件遇到不能计量的适配器 | 声明真实记账能力，或显式 `--accept-unmetered-budget` 记录缺口 |
| `no sandbox image is mapped for suite 'x' × runtime 'y' (needs: ...)` | 镜像表里没有这个配对 | 往 `agents/_runtime/images.yaml` 加一行，或 `--sandbox-image ref@sha256:... --sandbox-platform <arch>` |
| `is mapped to <image> (<platform>), but this run passes image=... platform=... — they must match` | 运行传的镜像/平台与表里的钉死行不一致 | 用表里那一个，或改表（并意识到证据身份随之变化） |
| `transcript: adapter is not instantiable without arguments (...)`（skipped） | 适配器需要构造参数，conformance 无法实例化 | 用真实实例跑轨迹检查，或让适配器可无参构造 |
| `read_trial_session() raised NotImplementedError: ...`（skipped） | 读取器还没实现 | 实现该 agent session 格式到 ATIF 的映射 |
| `read_trial_session() returned <T>, not a CanonicalTranscript` | 返回值类型不对 | 返回 `CanonicalTranscript`（含 `completeness`，否则 `cannot_judge` 永远不会触发） |
| `an agent declaration may only extend a base file (...)` | `extends` 指向了另一个 agent 的声明 | 只继承 `_` 前缀目录下的基座，共享事实放进自己的基座 |
| `budget_enforcement='gateway_lease' is enforced by an in-sandbox control stack, which this generator cannot write for you` | 用 `new-agent` 直接生成网关租约适配器 | 先用 `--budget none` 生成，等控制栈就绪后在类与声明里同时改 |
